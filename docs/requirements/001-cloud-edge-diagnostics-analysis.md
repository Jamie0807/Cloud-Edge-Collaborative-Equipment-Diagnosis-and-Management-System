# 001 云边协同设备诊断管理：业务需求分析

**状态：** Draft — **阻断：** D-001 至 D-014 尚未由用户确认，且工作树未具备批准的 monorepo bootstrap。
**来源：** 上游需求输入与项目治理规则。
**目的：** 形成可审阅、可拆分、尚未授权实现的业务需求基线。

## 1. 问题与边界

系统用于将三类感知终端采集的文件和元数据，经站内边端接入、保存、标准化和模拟分析后，可靠上报到云端，由云端保存、查询并在 Web 管理端展示。重点是可运行的主链路、可解释的数据归属、基本错误处理和可验证测试，不是精美 UI 或真实 AI 模型。

业务边界不可跨越：终端模拟器只访问边端；边端不让云端直接读取其本地文件或数据库；Web 只经云端 API 查询，不直接访问数据库。该特性应在已有治理基线和本 feature 的批准规格之后才进入代码实现。

## 2. 领域对象与身份语义

| 对象 | 核心职责 | 必须标识 | 关系 |
| --- | --- | --- | --- |
| 被监测设备（Asset） | 被诊断的电力设备 | `assetId` | 一个设备可关联多个终端和多个诊断事件 |
| 感知终端（Terminal） | 采集一种模态的数据并发送心跳/文件 | `terminalId` | 归属一个边端；配置关联站点、模态和采集周期 |
| 边端节点（Edge） | 终端接入、文件保存、标准化、分析、缓存、上报 | `edgeId` | 服务一个或多个终端；属于一个站点 |
| 检测/诊断事件（Event） | 一次采集及其产生的诊断结果 | `eventId` | 关联恰好一个 asset、terminal、edge；可带一个原始文件和一项分析结果 |
| 原始检测文件（Evidence） | 终端采集的图片或文件 | `eventId`、存储 URI/路径 | 先由边端安全保存，再作为分析证据及云端详情引用 |
| 模拟算法结果（Analysis Result） | 对单项文件的诊断输出 | `eventId` | 含缺陷类型、置信度、严重等级、分析时间和错误信息（若失败） |
| 边端运行状态（Edge Status） | 云端判断边端是否在线的心跳载荷 | `edgeId` | 含站点、CPU、内存、GPU/NPU、上报时间、最后接收时间 |

四个 ID 的语义必须独立，禁止把任一 ID 派生为另一个 ID 或仅保留组合字符串：

- `assetId`：被监测设备的业务主键，回答“哪台设备被诊断”。
- `terminalId`：采集装置主键，回答“哪个终端采集”。
- `edgeId`：边端节点主键，回答“由哪个站内节点接入、分析和上报”。
- `eventId`：一次检测事件的全链路唯一键，回答“这是哪一次采集/诊断”，也是重试幂等键的候选。

每个跨服务心跳、上传、缓存记录、云端诊断记录、查询响应都须分别出现与自身语义相符的 ID 字段；即使查询只按其中一项筛选，响应也不得省略其余关联 ID。

## 3. 端到端业务链路

```text
终端配置与本地测试文件
  ├─ 每 10 秒心跳 ───────────────────────────────> 边端：记录 terminal 状态/lastSeen
  └─ 按模态采集文件+元数据 ──────────────────────> 边端：校验、标准化、安全保存
                                                        │
                                                        ├─> 模拟算法：单项分析
                                                        ├─> 待上报缓存（outbox）
                                                        └─> 边端状态 + 诊断结果 ──────> 云端：持久化、幂等接收
                                                                                           │
                                                                                           └─> Web：列表、筛选、详情/证据地址
```

### 3.1 终端到边端

至少模拟三台可配置终端：红外、声纹、局放。它们每 **10 秒**发送一次心跳；红外每 **5 秒**、声纹每 **20 秒**、局放每 **60 秒**生成一次检测数据。每次采集应携带文件和可验证元数据，至少含 `assetId`、`terminalId`、`edgeId`、`eventId`、站点、模态、采集时间和原始文件名/类型。终端不能绕过边端向云端发送任何业务载荷。

边端记录 `terminalId`、模态、最后在线时间和运行状态；对上传执行必填字段、ID 一致性、模态白名单、时间格式、文件大小/类型、文件名和路径安全校验。成功后保存原始文件，生成规范化元数据，保留原始 `eventId`。

### 3.2 边端分析与缓存

边端把其受控目录中保存的文件路径，以及 `assetId`、`terminalId`、模态传给模拟算法。算法不需真实模型，但必须：验证输入；为成功分析返回缺陷类型、置信度和严重等级；为不可处理输入返回可记录错误；写入不含敏感数据的关键日志。

边端把规范化检测数据、分析结果和证据引用组装为标准化诊断结果，先写入本地待上报缓存，再由上报任务尝试发送。缓存记录应可辨识待发送/发送中/成功/可重试失败/终止失败，且把 `eventId` 作为唯一业务键，避免网络重试产生重复业务事件。

边端还须定时上报自身状态：`edgeId`、站点、CPU、内存、GPU/NPU、上报时间。题目未给出状态上报频率；为满足云端 60 秒离线判定，推荐默认 **10 秒**，且允许配置。

### 3.3 边端到云端与云端查询

云端接收边端状态并保存 `edgeId`、站点、最后在线时间和在线状态；距最后成功接收心跳 **超过 60 秒**时将该边端视为离线。时间比较应在云端执行，使用统一 UTC 时间源，页面状态以云端计算结果为准。

云端接收并幂等保存诊断结果，至少持久化四个 ID、模态、缺陷类型、置信度、严重等级、发生时间、分析/接收时间和证据文件地址。它管理设备、终端和边端之间的关系，并支持按设备、终端、边端、模态、时间范围查询。Web 通过云端 API 展示边端列表、诊断列表、详情和筛选结果。

## 4. 功能需求

| 编号 | 需求 |
| --- | --- |
| FR-001 | 可配置至少三台终端：红外、声纹、局放；配置含 `terminalId`、`edgeId`、站点、模态、`assetId`（或明确的资产映射）和采集周期。 |
| FR-002 | 每台终端每 10 秒向边端发送心跳；边端记录最后在线时间、模态和运行状态。 |
| FR-003 | 三类终端分别按 5/20/60 秒生成本地测试文件及元数据，并且只上报边端。 |
| FR-004 | 边端接收心跳、文件和元数据，校验并标准化字段，安全保存文件。 |
| FR-005 | 边端调用可失败、可记录日志的模拟单项分析，返回缺陷类型、置信度和严重等级。 |
| FR-006 | 边端形成保留四个 ID 的标准化诊断结果，并本地缓存待上报结果。 |
| FR-007 | 边端定时上报节点资源状态和诊断结果；网络恢复后可按重试策略补报。 |
| FR-008 | 云端接收边端状态；超过 60 秒未收到该 `edgeId` 的心跳时标为离线。 |
| FR-009 | 云端保存资产、终端、边端关系及诊断结果；相同 `eventId` 的重发不得产生重复记录。 |
| FR-010 | 云端查询支持 `assetId`、`terminalId`、`edgeId`、模态及时间范围组合过滤，并返回完整关联 ID。 |
| FR-011 | Web 有边端节点列表、诊断结果列表和诊断详情；诊断列表可按设备、边端和模态筛选，详情展示证据文件地址。 |
| FR-012 | 云端 API 提供清晰成功/校验/依赖异常响应并记录关键业务日志；至少有 2 个有效云端测试。 |

## 5. 非功能需求与可接受质量线

| 编号 | 要求 |
| --- | --- |
| NFR-001 | 系统须可在受控本地开发环境运行；容器化支持由 bootstrap 和部署决策确定；不依赖真实采集硬件或真实深度学习模型。 |
| NFR-002 | 每条跨服务消息契约明确字段类型、必填性、时间格式、枚举和失败响应，并做契约测试。 |
| NFR-003 | 终端/边端/云端异常可定位：结构化关键日志中包含相关 ID，但不得记录凭据或文件内容。 |
| NFR-004 | 上传必须防路径穿越、扩展名伪造和不可控大小；文件保存目录不得由客户端路径直接决定。 |
| NFR-005 | 重试安全：云端接收以 `eventId` 幂等，边端缓存不丢弃未获成功确认的事件。 |
| NFR-006 | UI 覆盖列表的加载、空数据、筛选失败/接口错误状态；Web 不直连数据库。 |
| NFR-007 | 新行为采用 TDD；Python 用 pytest、云端用 JUnit 5、Web 用 Vitest/Vue Testing Library，关键全链路用 Playwright，且通过项目质量门禁。 |
| NFR-008 | 首期范围以已验收的云边主链路为界，明确降级与未纳入能力；不得为未验证需求引入分布式复杂度。 |

## 6. 治理约束与范围外

项目治理规定目录职责：`apps/web` 为 Vue 3 管理端，`apps/cloud-api` 为 Spring Boot 云端 API，`apps/edge-service` 和 `apps/terminal-simulator` 为 Python 服务，`packages/contracts` 为跨服务契约。该职责边界不等同于对 D-001 至 D-014 任一具体方案、版本、协议、认证或存储选项的批准。

本初稿和后续首个 feature 不把下列内容当作必做：真实硬件接入、真实深度学习推理、生产多租户、复杂权限模型、跨站点高可用、自动部署、精致视觉设计、终端直接访问云端、云端直接读取边端文件系统。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 多个运行单元并行变更 | 主链路和契约漂移 | 先完成一条受控模态链路的自动化验证，再在同一批准契约下复用到其余模态；未验证能力不进入范围。 |
| 不明确的文件云端可访问方式 | 详情证据地址失效或越权 | 在实现前确认 D-007；将 URI 存储/访问授权纳入契约测试。 |
| 网络重试导致重复诊断 | 数据重复、列表错误 | D-009 的 `eventId` 唯一约束、边端 outbox 和幂等 API 是实现前置条件。 |
| 时钟偏差使离线误判 | 在线状态不可信 | 接收方记录服务器接收时间，统一 UTC；自动化测试覆盖阈值和最后接收时间。 |
| 终端上传不受控文件 | 路径穿越、磁盘耗尽、恶意内容 | 白名单、大小上限、随机存储名、受控目录、拒绝客户端路径；后续可补恶意文件扫描。 |
| 将 ID 混用或省略 | 查询/追溯错误，违反项目约束 | 契约 schema、数据库列、日志字段和端到端测试都断言四个 ID 独立存在。 |
| 云端/边端技术选择未确认 | 未授权实现或实现返工 | 保持 Draft 阻断；仅在用户确认后将实际选择锁定至 spec、plan 和必要 ADR。 |

## 9. 推荐的首期交付策略

推荐以“单一受控链路先验证、三种模态在同一契约下复用”为实施策略。Python/FastAPI、HTTP multipart、持久 outbox、Spring Boot/MySQL/Flyway、Vue 3/Vite、MinIO 与容器化启动均仅为推荐组合，未获确认前不得写入实现或视为已批准。该组合的目标是明确通信、存储、重试、离线和查询责任，而不是替代用户决策。

在获得 D-001 至 D-014 的确认前，`spec.md`、`plan.md`、`tasks.md` 保持 Draft。任何实现任务只能引用已确认的决策；未决项必须在实施前被确认或显式降低范围。
