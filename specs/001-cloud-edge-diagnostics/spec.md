# 001 云边协同设备诊断管理规格

**状态：** Approved for implementation planning — 业务编码尚未开始。
**分析依据：** [`docs/requirements/001-cloud-edge-diagnostics-analysis.md`](../../docs/requirements/001-cloud-edge-diagnostics-analysis.md)
**前置门槛：** 已确认的 D-001 至 D-014 必须保持与实现计划、契约测试和 ADR 一致；生产容量、恢复、数据生命周期参数必须在对应实现任务前补齐。

## 1. 目标与范围

构建可在本地和可复现部署环境运行的云边协同设备诊断管理主链路：三类感知终端只向边端发送心跳和检测文件；边端接入、保存、标准化、模拟分析并缓存上报；云端持久化、判断边端离线、支持查询；Web 展示节点和诊断结果。所有链路均独立保留 `assetId`、`terminalId`、`edgeId`、`eventId`。

## 2. 用户故事

### US-001 终端采集与上报（优先级 P1）

作为系统运维人员，我要配置红外、声纹、局放三台终端，让它们按规定周期生成本地测试文件、每 10 秒向其所属边端心跳，并只将文件和元数据发送给边端，以保证终端不绕过边端链路。

**验收场景**

1. 给定已配置的红外、声纹、局放终端，当运行模拟器时，则它们分别每 5、20、60 秒生成检测事件，且心跳间隔为 10 秒。
2. 给定一次采集，当终端上传文件和元数据时，则载荷包含并分别表达 `assetId`、`terminalId`、`edgeId`、`eventId`、模态和采集时间。
3. 给定任一终端，当其发送业务载荷时，则目标仅是配置的边端地址，而非云端地址。

### US-002 边端接入、分析和缓冲（优先级 P1）

作为站内运维者，我要让边端接收终端心跳/文件，校验并安全保存文件，执行模拟诊断，再持久缓存待上报结果，使现场采集可在云端暂不可达时继续被处理。

**验收场景**

1. 给定有效文件和元数据，当边端接收上传时，则记录终端最后在线时间和状态，在受控目录保存文件，并产生规范化记录。
2. 给定有效保存文件，当模拟算法成功时，则结果含缺陷类型、置信度、严重等级以及原始四个 ID。
3. 给定缺少必填 ID、模态不合法、文件类型/大小不合法或不安全路径，当边端接收上传时，则拒绝该请求、不保存不可信文件，并返回明确校验错误。
4. 给定算法输入无效或算法异常，当执行分析时，则记录关联 ID 的错误，且不把虚构诊断结果标为成功。
5. 给定云端不可用，当边端产生诊断结果时，则本地待上报缓存保留该事件，待后续上报重试。

### US-003 边端状态与可靠上报（优先级 P1）

作为云端管理员，我要接收每个边端的资源状态和诊断结果，并能在重试时避免重复事件，以获得可信的节点和诊断数据。

**验收场景**

1. 给定边端状态上报，当云端接收它时，则保存 `edgeId`、站点、CPU、内存、GPU/NPU、上报/接收时间。
2. 给定缓存诊断事件，当上报成功时，则云端保存完整字段，边端只在成功确认后把该事件标为已发送。
3. 给定同一 `eventId` 的重复上报，当云端接收时，则返回幂等成功或等价结果，且仅有一条业务诊断记录。
4. 给定一次失败上报，当网络恢复时，则边端按已确认的重试策略补报，且四个 ID 与第一次上报一致。

### US-004 云端关系管理、离线判断与查询（优先级 P1）

作为云端管理员，我要保存设备、终端、边端关系，按规则判断边端离线，并按多个维度查询诊断结果，以便追溯现场数据。

**验收场景**

1. 给定边端的最后成功接收心跳，当云端当前接收时间超过其 60 秒时，则该 `edgeId` 显示为离线；60 秒内显示为在线。
2. 给定诊断结果，当存储时，则保存 `assetId`、`terminalId`、`edgeId`、`eventId`、模态、缺陷类型、置信度、严重等级、发生时间和证据文件地址。
3. 给定一个或多个 `assetId`、`terminalId`、`edgeId`、模态和时间范围条件，当调用查询接口时，则结果仅符合全部已给条件，并仍返回完整关联 ID。
4. 给定没有匹配记录，当查询时，则返回可区分于错误的空集合/分页结果。

### US-005 Web 管理与证据查看（优先级 P1）

作为管理端使用者，我要查看边端状态、诊断结果列表和诊断详情并筛选，使我能定位异常设备及其证据地址。

**验收场景**

1. 边端节点列表显示边端编号、所属站点、在线状态和最后在线时间。
2. 诊断列表显示设备、终端、边端、模态、缺陷类型、置信度、严重等级和发生时间，并可以按设备、边端、模态筛选。
3. 诊断详情显示完整诊断字段和证据文件地址。
4. 列表和详情在加载、空数据、云端 API 错误时呈现清晰状态；Web 不直接读取数据库。

## 4. 业务规则

1. 云端对边端离线的唯一强制阈值是：自该边端最后一次成功心跳接收时间起 **超过 60 秒**即离线。
2. `eventId` 表示一次采集/诊断事件，在终端、边端缓存、云端 API 和云端数据模型中保持相同值；不使用“每次重试的新 ID”。
3. 文件成功保存和元数据标准化是调用算法的前置条件；算法只读取边端保存后的受控路径。
4. 云端查询和 Web 返回应保留四个 ID，即使调用方仅按其中一个过滤。
5. 上报失败不可删除待上报事件；重复交付必须由云端幂等处理。

### 4.1 消息类型与标识字段矩阵

| 消息类型              | 必填标识                                     | 约束                                                        |
| --------------------- | -------------------------------------------- | ----------------------------------------------------------- |
| 终端心跳              | `terminalId`、`edgeId`                       | `assetId`、`eventId` 不适用，不伪造、不拼接。               |
| 边端状态上报          | `edgeId`                                     | `assetId`、`terminalId`、`eventId` 不适用，不伪造、不拼接。 |
| 检测文件上传          | `assetId`、`terminalId`、`edgeId`、`eventId` | 四个字段独立且必须与已注册关系一致。                        |
| 诊断结果上报/查询响应 | `assetId`、`terminalId`、`edgeId`、`eventId` | `eventId` 全局唯一；重复载荷字段不一致时拒绝并告警。        |

同一 `eventId` 的重放返回幂等结果，不创建新事件；若重放载荷与首次载荷的业务字段不一致，必须返回冲突错误并保留审计记录。

## 5. 非功能需求

- 时间字段采用 ISO-8601 UTC；云端以其接收时间而非终端上报时间做 60 秒离线计算。
- 文件上传使用受控存储名与目录，限制类型和大小，拒绝客户端给出的路径；日志不输出机密、令牌或文件正文。
- 接口有一致的成功、校验失败、未找到、依赖不可用和幂等重放语义。
- 所有新增可观察行为先写失败测试；跨服务消息以 schema/契约测试验证四个 ID、必填字段和失败响应。
- 生产迭代优先以一个端到端诊断事件建立契约、观测和恢复能力，再复用相同契约完成另两种模态。

## 6. 范围外

- 真实采集硬件协议、真实红外/声纹/局放文件解析和真实深度学习模型。
- 终端直接调用云端，云端直接读取边端本地文件系统或数据库。
- 多站点高可用、集群消息队列、跨区域灾备、自动伸缩、完整运维平台可作为后续版本，但必须由版本边界和风险接受记录明确批准，不得以未声明的交付压力为排除理由。
- 多租户、完整生产级 IAM 平台、审计合规认证和外网部署不属于本 feature 的实现范围；本期仍必须实现已批准的服务身份、JWT 校验边界、关键操作审计字段和证据生命周期参数，并在运行文档中记录后续补齐计划。
- UI 视觉精修不是 v1 核心，但可访问性、信息完整性、错误状态和操作可用性属于正式验收要求。

## 7. 实现前置与验收条件

通信、技术栈、存储、认证、文件存储、重试和分页策略已逐项记录在分析文档 D-001 至 D-014，并由用户确认或授权采用调研后的推荐值。以下内容仍是实现前的工程验收条件：

1. 迁移、契约、服务身份、对象存储访问和错误码均有可执行测试。
2. outbox 崩溃恢复、有限重试、人工重放和幂等重发均有测试证据。
3. 生产容量、RTO/RPO、备份恢复、证据保留/删除周期在运行文档中明确。

已选方案见分析文档第 7、9 节及 [`docs/adr/001-cloud-edge-storage-security-reliability.md`](../../docs/adr/001-cloud-edge-storage-security-reliability.md)。即使 bootstrap 质量门禁已通过，仍必须通过本 feature 的 TDD、契约测试、集成测试和自主验收后才能声明完成。
